# Record formats, Vericairn 0.7.3

Vericairn 0.7.3 reads record formats 1 and 2 and writes an estate's own format, at most 2. It retains the `work-progress`, `communication-setting`, `communication-delegation` and `harness-qualification` additions shipped in 0.7.1 and retains 0.7.2's worker observation fields. FIX-19, UPDATE-01, FIX-20 and FIX-21 change no record fields; FIX-22 adds derived attention to API v1 responses without changing records. The five changes introduce no new record format. Context and hand-over packages are derived artifacts, not new record formats. Older builds do not understand these additions merely by understanding format 2. Two documents describe the formats, and this set carries both as frozen copies:

- `record-format-v1.md`: record format 1, the base of both formats: the envelope, the canonical form and the content hash, signatures, where records live, and the rules every record keeps.
- `record-format-v2.md`: what record format 2 changes: the format each record states, migration, types and fields, goal predicates and evaluations, worker accounting and execution, progress, communication and delegation, harness qualification, routing and asks, living documents, pairing, persistent device identity and emergency access.

Which rules apply to a record follows the format the record states in its `format` field, never the estate's, with one exception, for admissions: in an estate at record format 1 an unsigned admission counts while the charter leaves signatures optional, as format 1 has it, and in an estate at format 2 an admission, admitting or revoking, counts only when it is signed or listed by the operator's signed move to format 2, whatever format or date it states. Otherwise: a record written in format 1 keeps format 1's rules in an estate at either format, and a record written in format 2 follows format 1's rules except where `record-format-v2.md` says otherwise. An estate already at format 2 stays at format 2 when upgraded from 0.7.2 to 0.7.3. An estate's manifest states the format its new records are written in (`recordFormat`); a new estate starts at 2, and `vericairn estate upgrade --to 0.7.3` moves an estate at 1 to 2 without rewriting a record. `record-reference.md` lists every type and field and marks those format 2 introduced, and `vericairn records describe <type>` shows the same from the build.
