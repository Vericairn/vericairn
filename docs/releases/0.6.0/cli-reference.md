# Command-line reference, Vericairn 0.6.0

Generated by the build tooling (`vericairn-docs generate`) from the command tree of build 0.6.0-dev+e251b9642be39def864c8ec8ea052d3a80016b1b on 2026-10-16. Every command and verb is listed; nothing here is written by hand. Global options apply to every command: `--estate <path>` names the estate root (default: the current directory), `--json` switches to machine-readable output, `--version` prints the version, `--help` prints the usage of any command.

## `vericairn records`

Create, validate, describe and format records.

Usage: `vericairn records [command] [options]`

Verbs: `validate`, `new`, `describe`, `format`, `hash`

### `vericairn records validate`

Parse and validate every record and the manifest of an estate.

Usage: `vericairn records validate [options]`

### `vericairn records new`

Create a record in canonical form, validate the estate with it, and write it.

Usage: `vericairn records new <type> [options]`

Arguments:
- `<type>`: Record type, for example work-order.

Options:
- `--by <by>`: Authoring principal id (ULID). Required.
- `--body <body>`: Path to a JSON file holding the body, or '-' for standard input. Required.
- `--subject <subject>`: Subject as type:id or type:id:hash.
- `--supersedes <supersedes>`: Id of the record this one replaces.
- `--at <at>`: Authoring time, for example 2026-10-13T14:00:00Z (default: now).
- `--id <id>`: Explicit record id; only the root operator principal needs this.

### `vericairn records describe`

Explain record types and their fields.

Usage: `vericairn records describe [<type>] [options]`

Arguments:
- `<type>`: Record type to describe; omit to list all types.

### `vericairn records format`

Rewrite record files in canonical pretty form without changing their content or hash.

Usage: `vericairn records format <files>... [options]`

Arguments:
- `<files>...`: Record files to rewrite in canonical pretty form.

### `vericairn records hash`

Print the computed content hash of a record file.

Usage: `vericairn records hash <file> [options]`

Arguments:
- `<file>`: Record file.

## `vericairn estate`

Create and check estates.

Usage: `vericairn estate [command] [options]`

Verbs: `init`, `check`, `export`, `restore`, `upgrade`, `reconcile`

### `vericairn estate init`

Create a new estate: operator principal, charter and manifest, validated together.

Usage: `vericairn estate init [options]`

Options:
- `--profile <profile>`: Storage profile: repository-synced (records as files in a git repository) or local-only (records in this machine's live store). Default: repository-synced.
- `--name <name>`: Estate display name. Required.
- `--slug <slug>`: Estate slug (lower-case kebab-case). Required.
- `--purpose <purpose>`: Why the estate exists. Required.
- `--operator-name <operator-name>`: Display name of the root operator (a human). Required.
- `--organization <organization>`: Organization display name. Required.
- `--github <github>`: GitHub organization login, if any.
- `--repository <repository>`: GitHub owner/name of the Vericairn source to pin. Default: Vericairn/vericairn.
- `--commit <commit>`: Commit of the Vericairn source to pin (40 hex digits). Required.

### `vericairn estate check`

Validate records and run repository cleanliness and portability checks.

Usage: `vericairn estate check [options]`

### `vericairn estate export`

Write a verified export: records, objects, manifest and documents with an inventory; no keys or authority.

Usage: `vericairn estate export [options]`

Options:
- `--out <out>`: Path of the export file to create (never overwritten). Required.
- `--by <by>`: Principal id recorded as the exporter.

### `vericairn estate restore`

Verify an export against its inventory and restore it into an empty directory as a repository-synced estate; authority is not restored.

Usage: `vericairn estate restore [options]`

Options:
- `--from <from>`: Export file. Required.
- `--to <to>`: Empty destination directory. Required.

### `vericairn estate upgrade`

Pin the estate to a published release and apply record-format migrations as one reviewable change with a migration record.

Usage: `vericairn estate upgrade [options]`

Options:
- `--to <to>`: Version of a published release recorded in this estate. Required.
- `--by <by>`: Principal id applying the upgrade (required unless --check).
- `--check`: Show the plan without changing anything.

### `vericairn estate reconcile`

List what two diverged copies left to settle: divergent revisions, duplicate keys, duplicate results.

Usage: `vericairn estate reconcile [options]`

Briefs, assignments, attempts, results and amendments of work orders.

### `vericairn work result`

### `vericairn work takeover`

Take over a step an agent holds: the hand-over is a new assignment of the step to a person, carrying the agent's brief and naming the agent's assignment, which holds the step from then on; every run of the agent's assignment still in flight is asked to stop. A person records it, the one taking the step over, the sponsor of its goal or an operator, never an agent.

Usage: `vericairn work takeover <assignment> [options]`

Arguments:
- `<assignment>`: Assignment record id.

- `--by <by>`: Authoring principal id (ULID). Required.

## `vericairn goal`

Goals: objectives the estate carries out, done when their record predicates hold, an evaluator who did none of the work finds every condition met, and they are accepted. Without a subcommand, the current goal condition by condition: the one goal neither achieved nor ended, or with none or several, the list.

Usage: `vericairn goal [command] [options]`

Verbs: `show`, `next`, `propose`, `activate`, `pause`, `resume`, `stop`, `custody-exception`, `step`, `evaluate`, `accept`

### `vericairn goal show`

Show a goal condition by condition: its status, the budget its activation grants, each condition's verdict with the records it read beside its current evaluation's, its steps, and what stands between it and its acceptance.

Usage: `vericairn goal show [<goal>] [options]`

Arguments:
- `<goal>`: Goal record id (any revision); omit for the current goal.

### `vericairn goal next`

Show a goal's next steps routed from this machine: each eligible step with the principal its role's roster reaches (an agent where a launcher for its harness, its admitted key and the goal's budget allow, a person where needed, a reserved action only to one who holds it) or why none is available, whether the goal's budget allows it, and what holds the others. It records and starts nothing; vericairn goal step takes the next one.

Usage: `vericairn goal next [<goal>] [options]`

Arguments:
- `<goal>`: Goal record id (any revision); omit for the current goal.

### `vericairn goal propose`

Propose a goal, or a revision of one: what done looks like, its constraints, its budget and its sponsor. A proposal authorizes and funds nothing. Anyone may propose a goal; a revision is its sponsor's when the sponsor is a person, and an operator's when an agent sponsors it, and anyone else proposes the change as an ask.

Usage: `vericairn goal propose [options]`

Options:
- `--by <by>`: Acting principal id (ULID). Required.
- `--title <title>`: Short title. Required.
- `--objective <objective>`: What the sponsor wants, in the sponsor's words. Required.
- `--done <done>`: A completion condition as JSON; repeatable. A record predicate, {"type": ...} with optional subject, product, fields, state, min and max (or the same inside {"record": ...}), or an evidence statement, {"evidence": ..., "check": ...}. Required.
- `--sponsor <sponsor>`: The accountable principal; the proposer when omitted. A person who sponsors a goal activates and accepts it; a goal an agent sponsors is activated and accepted by an operator, and only an operator.
- `--delegate <delegate>`: A principal the sponsor, a person, delegates the acceptance of an ordinary goal to; it accepts while it holds the 'accept-work' scope, and never a goal that includes a reserved action.
- `--constraint <constraint>`: What must not change or happen; repeatable.
- `--budget <budget>`: A cap its activation grants, unit=value; repeatable: wallMinutes and attemptsPerStep (both required), tokens, concurrency, or currency=<amount in minor units>:<unit> such as currency=5000:USD. A unit not given is not granted.
- `--roster <roster>`: The roster record whose roles it uses; the estate's current roster when omitted.
- `--kind <kind>`: finite (ends when done) or stewardship (holds a standing condition). Default: finite.
- `--work-order <work-order>`: A work order the sponsor gives as its plan; repeatable. Without one a planner proposes its work, as work orders that name the goal among their inputs.
- `--input <input>`: A record it builds on, as type:id; repeatable.
- `--deadline <deadline>`: The goal's deadline, for example 2026-12-01T00:00:00Z; validated and recorded but not yet enforced.
- `--supersedes <supersedes>`: The goal this proposal revises, by its current revision's id; a revision needs a fresh activation, and only its sponsor, a person, or an operator for a goal an agent sponsors records it.

### `vericairn goal activate`

Activate a proposed goal, which grants its budget: by its sponsor, a person who holds the operator role or a grant of the spending scope, or by an operator when an agent sponsors it. An agent never activates a goal.

Usage: `vericairn goal activate <goal> [options]`

Arguments:
- `<goal>`: Goal record id (any revision).

Options:
- `--by <by>`: Acting principal id (ULID). Required.
- `--note <note>`: Why, and what remains; a sentence naming the action when omitted.

### `vericairn goal pause`

Pause an active goal; its sponsor's, or an operator's for a goal an agent sponsors. Prevents new runs but does not stop runs already in flight; use 'vericairn worker stop' for each run that must stop.

Usage: `vericairn goal pause <goal> [options]`

Arguments:
- `<goal>`: Goal record id (any revision).

Options:
- `--by <by>`: Acting principal id (ULID). Required.
- `--note <note>`: Why, and what remains; a sentence naming the action when omitted.

### `vericairn goal resume`

Resume a paused, budget-limited or blocked goal, which grants its budget again; by whoever may activate it.

Usage: `vericairn goal resume <goal> [options]`

Arguments:
- `<goal>`: Goal record id (any revision).

Options:
- `--by <by>`: Acting principal id (ULID). Required.
- `--note <note>`: Why, and what remains; a sentence naming the action when omitted.

### `vericairn goal stop`

Stop a goal: its sponsor, or an operator for a goal an agent sponsors, ends it as abandoned and prevents new runs. Runs already in flight are not stopped; use 'vericairn worker stop' for each run that must stop.

Usage: `vericairn goal stop <goal> [options]`

Arguments:
- `<goal>`: Goal record id (any revision).

Options:
- `--by <by>`: Acting principal id (ULID). Required.
- `--note <note>`: Why, and what remains; a sentence naming the action when omitted.

### `vericairn goal custody-exception`

Record the sponsor's exception to the custody precondition for a goal's current revision: until it expires, a coding agent's run of the goal may launch unattended on a machine where a key of an operator or of the sponsor signs without its owner's presence, and the run names the exception. Recorded only by the goal's sponsor, or by an operator when an agent sponsors it; a revised goal needs a fresh one.

Usage: `vericairn goal custody-exception <goal> [options]`

Arguments:
- `<goal>`: Goal record id (any revision).

Options:
- `--by <by>`: Acting principal id (ULID). Required.
- `--reason <reason>`: Why unattended runs of the goal may launch while such a key signs where they run. Required.
- `--expires <expires>`: When the exception stops being in force, for example 2026-10-20T00:00:00Z. Required.

### `vericairn goal step`

Take a goal's next step, one at a time: its first eligible step whose route acts, routed from this machine by the goal's roster, for an operator, the goal's sponsor when a person, or a principal holding local-engineering. An agent's step goes on with the assignment that holds it, or is assigned to the agent with the run's intent, after the worker's whole preflight, and its run starts through the worker; every refusal before the intent records nothing, the assignment included, as while a key of an operator or of the sponsor signs here without presence and no custody exception is in force. A person's step is assigned to the person and asked of them, the two recorded together; a step no principal is available for is asked of the sponsor, never given to another contributor. It activates, funds, accepts and answers nothing.

Usage: `vericairn goal step [<goal>] [options]`

Arguments:
- `<goal>`: Goal record id (any revision); omit for the current goal.

Options:
- `--by <by>`: Acting principal id (ULID). Required.
- `--repository <repository>`: For an agent's step, the repository resource whose clone, registered on this machine (vericairn sources clone), its workspace is made from.
- `--setting <setting>`: For an agent's step, a setting of the launcher routing chose, as name=value, for example command=<executable or JSON array>; repeatable.
- `--wall-minutes <wall-minutes>`: For an agent's step, the run's cap in wall minutes; what remains of the goal's budget when omitted, and never more.
- `--branch <branch>`: For an agent's step, the work branch; work/ and the work order's key when omitted.
- `--base <base>`: For an agent's step, what a new work branch starts from; the clone's HEAD when omitted.
- `--detach`: Return once an agent's run is launched, leaving it to the daemon that serves the estate; without it the command waits until the run settles, and Ctrl+C asks it to stop.

### `vericairn goal evaluate`

Record the evaluation of a goal's current revision, condition by condition, with the records each verdict read; by a principal other than any step's author.

Usage: `vericairn goal evaluate <goal> [options]`

Arguments:
- `<goal>`: Goal record id (any revision).

Options:
- `--by <by>`: Acting principal id (ULID). Required.
- `--summary <summary>`: What was reviewed and how. Required.
- `--verdict <verdict>`: A condition's verdict, n:verdict:reason with n from 1 and the verdict met, not-yet or impossible; repeatable. Every evidence statement needs one; a record predicate gets the runtime's, unless the evaluator judges one the runtime does not find met impossible.
- `--read <read>`: A record the evaluator read for a condition, n:record-id; repeatable. An evidence statement found met names at least one.

### `vericairn goal accept`

Accept a goal at its current revision, relying on its current evaluation: by its sponsor when the sponsor is a person, or the principal the sponsor delegated an ordinary goal's acceptance to, and by an operator, only an operator, when an agent sponsors it; never by its evaluator or a step's author, and only once every condition is found met and every record predicate holds.

Usage: `vericairn goal accept <goal> [options]`

Arguments:
- `<goal>`: Goal record id (any revision).

Options:
- `--by <by>`: Acting principal id (ULID). Required.
- `--statement <statement>`: What is accepted and on what basis. Required.

## `vericairn worker`

The worker (vericairn.worker/1): a coding agent carries one assignment toward its exit question through a launcher, in a workspace on a work branch, with its cap from its goal's budget recorded before it starts and its observed usage after. It accepts nothing; the agent's result is a claim another principal reviews.

Usage: `vericairn worker [command] [options]`

Verbs: `launchers`, `run`, `stop`, `runs`

### `vericairn worker launchers`

List the coding-agent launchers available to the runtime, providers of vericairn.launcher.agent/1, with their settings and limitations.

Usage: `vericairn worker launchers [options]`

### `vericairn worker run`

Run a coding agent on an assignment: refused while the goal is not active or its budget is spent, while a device of an operator or the goal's sponsor signs here without presence and the sponsor recorded no custody exception in force for the goal, or when the launcher cannot run; otherwise the workspace is prepared, the intent recorded with the cap, the harness launched with the brief and the MCP server, observed, and its usage recorded once it exits.

Usage: `vericairn worker run <assignment> [options]`

Arguments:
- `<assignment>`: The assignment the agent carries, whose contributor it is.

Options:
- `--launcher <launcher>`: The launcher: claude-code, codex or generic (generic process launch is not complete agent support). Required.
- `--agent <agent>`: The agent principal the harness acts for: the assignment's contributor, with an admitted device whose key this machine holds. Required.
- `--by <by>`: The principal recording the run: the operator, the goal's sponsor when the sponsor is a person, or a principal with the local-engineering scope. Required.
- `--repository <repository>`: The repository resource whose clone, registered on this machine (vericairn sources clone), the workspace is made from. Required.
- `--goal <goal>`: The goal the run is charged to, when the work belongs to more than one active goal.
- `--branch <branch>`: The work branch; work/ and the work order's key when omitted. A later run of the branch continues in its workspace.
- `--base <base>`: What a new work branch starts from; the clone's HEAD when omitted.
- `--wall-minutes <wall-minutes>`: The run's cap in wall minutes; what remains of the goal's budget when omitted, and never more.
- `--setting <setting>`: A launcher setting as name=value, for example command=<executable or JSON array>; repeatable.
- `--detach`: Return once the harness is launched, leaving the run to the daemon that serves the estate; without it the command waits until the run settles, and Ctrl+C asks it to stop.

### `vericairn worker stop`

Ask a run to stop and report what was observed: the request, its transmission to the harness, the harness's acknowledgment, an escalation after the grace period and the containment, each only once observed. A stop that is not observed is reported as requested.

Usage: `vericairn worker stop <run> [options]`

Arguments:
- `<run>`: The run: its id, the id of any of its operation's revisions, or its identity.

Options:
- `--by <by>`: The principal asking for the stop. Required.
- `--reason <reason>`: Why.
- `--grace <grace>`: Seconds the harness has to stop once the stop is transmitted before its process tree is killed; the worker's default, ten, when omitted.

### `vericairn worker runs`

List the agent runs with their caps, their observed usage, what each is charged (its cap for what was not reported, and while in flight) and their stops, and the ledgers of their goals.

Usage: `vericairn worker runs [options]`

## `vericairn devices`

Device keys: create a device for a principal on this machine, pair one on another machine, list, admit, revoke, rename and rotate, and the operator's recovery device.

Usage: `vericairn devices [command] [options]`

Verbs: `create`, `list`, `admit`, `revoke`, `recovery`, `pair`, `writes`, `rename`, `rotate`

### `vericairn devices create`

Generate a key on this machine and record the device, signed by its own key.

Usage: `vericairn devices create [options]`

Options:
- `--principal <principal>`: The principal this device acts for. Required.
- `--name <name>`: Descriptive device name, never a machine path. Required.
- `--custody <custody>`: Key custody: default, the strongest this machine offers (CNG on Windows; the Secure Enclave on a Mac that has one; the secret service on Linux where one runs; else an owner-only file), or file, cng, secure-enclave or secret-service.
- `--presence <presence>`: Every signature needs its owner's presence (Touch ID or the login password; Secure Enclave custody only, never for an agent). Default: a person's device needs it wherever its custody enforces it; '--presence false' declines.
- `--profile <profile>`: Permitted connectivity profile; repeatable (default: embedded).

### `vericairn devices list`

List device records with their admission state and whether their key is held here.

Usage: `vericairn devices list [options]`

### `vericairn devices admit`

Admit a device to author records in this estate (operator or 'administer' scope).

Usage: `vericairn devices admit <device> [options]`

Arguments:
- `<device>`: Device record id.

Options:
- `--by <by>`: Authoring principal id (ULID). Required.
- `--note <note>`: Why the device is admitted. Required.
- `--recovery <recovery>`: Sign with the operator's recovery key in this file, when no admitted device of the operator is left; asks for its passphrase. Every use stays in 'status' until the operator reviews it.
- `--passphrase-stdin`: Read the recovery key's passphrase from the first line of standard input instead of the terminal.

### `vericairn devices revoke`

Revoke a device's admission from now on; its earlier records stay attributable.

Usage: `vericairn devices revoke <device> [options]`

Arguments:
- `<device>`: Device record id.

Options:
- `--by <by>`: Authoring principal id (ULID). Required.
- `--reason <reason>`: Why the admission ends. Required.
- `--recovery <recovery>`: Sign with the operator's recovery key in this file, when no admitted device of the operator is left; asks for its passphrase. Every use stays in 'status' until the operator reviews it.
- `--passphrase-stdin`: Read the recovery key's passphrase from the first line of standard input instead of the terminal.

### `vericairn devices recovery`

Make the operator's recovery device for emergency access: its key is written once to a file, encrypted with a passphrase you type, and never held by this machine; an admitted device of the operator held here admits it (record format 2).

Usage: `vericairn devices recovery [options]`

Options:
- `--principal <principal>`: The operator the recovery device acts for. Required.
- `--name <name>`: Descriptive name, for example where the key is kept; never a machine path. Required.
- `--output <output>`: New file to write the encrypted key to, outside the estate's repository; move it off this machine at once. Required.
- `--passphrase-stdin`: Read the recovery key's passphrase from the first line of standard input instead of the terminal.

### `vericairn devices pair`

Issue a pairing code for a new device on another machine: 16 characters, valid ten minutes, for one device and five attempts. Entered there with 'vericairn connections add', it records the device with the key it presents and admits it under your authority (needs the runtime serving the local-network profile).

Usage: `vericairn devices pair [options]`

Options:
- `--principal <principal>`: The principal the new device will act for. Required.
- `--by <by>`: The administrator: the operator, or a principal holding the 'administer' scope, whose admitted device on this machine signs the admission. Required.
- `--profile <profile>`: A connectivity profile the device will be permitted; repeatable (default: local-network).

### `vericairn devices writes`

List what paired devices wrote over the local network through this machine's runtime: when, which device, for which principal, the operation and the record it produced. A record a paired device asks for is signed by a device of the same principal held here, so this is where the paired device behind it is kept.

Usage: `vericairn devices writes [<device>] [options]`

Arguments:
- `<device>`: A paired device's id, to list its writes only.

### `vericairn devices rename`

Rename a device whose key is held here; it keeps its identity, key and admission (record format 2).

Usage: `vericairn devices rename <device> [options]`

Arguments:
- `<device>`: Device record id.

Options:
- `--name <name>`: The device's new descriptive name, never a machine path. Required.

### `vericairn devices rotate`

Replace a device's key with a new one, signed by both keys; the device keeps its identity and admission, and its earlier records stay valid (record format 2).

Usage: `vericairn devices rotate <device> [options]`

Arguments:
- `<device>`: Device record id.

Options:
- `--custody <custody>`: Custody of the new key: file, cng, secure-enclave, secret-service, or default for the strongest this machine offers (when omitted: the custody the device has).
- `--presence <presence>`: Every signature with the new key needs its owner's presence (Secure Enclave custody only, never for an agent); '--presence false' removes it. Default: the device's presence, where the new custody enforces it.

## `vericairn connections`

The runtimes this machine reaches over the local network: add one by pairing with a code, list them with their state, and remove one. Kept for this user on this machine, never in a repository.

Usage: `vericairn connections [command] [options]`

Verbs: `add`, `list`, `remove`

### `vericairn connections add`

Pair this machine with the runtime at an address using a code an administrator issued: the runtime proves it knows the code and who it is, this machine makes its device key and presents it, and the runtime records and admits the device. The connection pins the runtime's identity.

Usage: `vericairn connections add <address> [options]`

Arguments:
- `<address>`: Where the runtime listens: its address and port, as the pairing code's administrator gave them, for example 192.168.1.20:7443.

Options:
- `--code <code>`: The pairing code, as shown: five groups of four characters. Required.
- `--name <name>`: This device's descriptive name, never a machine path. Required.
- `--custody <custody>`: Key custody: default, the strongest this machine offers, or file, cng, secure-enclave or secret-service.
- `--presence <presence>`: Every signature needs its owner's presence (Secure Enclave custody only, never for an agent). Default: a person's device needs it wherever its custody enforces it; '--presence false' declines.

### `vericairn connections list`

Check every connection now and show its state: current, partial, denied, cached (with when it was last current) or unavailable.

Usage: `vericairn connections list [options]`

### `vericairn connections remove`

Forget a connection on this machine. The device stays admitted until an administrator revokes it, since disconnection is never revocation, and its key stays in this machine's custody.

## `vericairn release`

Usage: `vericairn release [command] [options]`

### `vericairn release list`

### `vericairn release providers`

Usage: `vericairn release providers [options]`

### `vericairn release submit`

Record the intent, then dispatch the build through the provider; the run id and outcome are recorded as they are observed. Never publishes.

Usage: `vericairn release submit [options]`

Options:

- `--version <version>`: The version to release, for example 0.4.0. Required.

Usage: `vericairn release observe [options]`

- `--version <version>`: The version to release, for example 0.4.0. Required.
- `--by <by>`: Principal id recording the operation (ULID). Required.
- `--product <product>`: Product record id, to find the operation by product and version.
- `--provider <provider>`: The provider id, for example github-releases; the product's declared provider when omitted.
- `--repository <repository>`: The setting repository (for GitHub, owner/name of the repository whose workflow builds the release).
- `--qualified <qualified>`: Platform whose qualification is recorded for the candidate; repeatable.
- `--limitation <limitation>`: A known limitation of the candidate; repeatable.
- `--signing <signing>`: Signing state recorded on the candidate. Default: unsigned developer build.
- `--cancel <cancel>`: Settle an intent that was never dispatched, or an outcome reconciled as having had no effect, with this reason.

## `vericairn runtime`

The daemon that owns an estate's live state on this machine: serve, start, stop, status, install, uninstall, configure (the local-network profile) and rotate (its certificate).

Usage: `vericairn runtime [command] [options]`

Verbs: `serve`, `start`, `stop`, `status`, `install`, `uninstall`, `configure`, `rotate`

### `vericairn runtime serve`

Serve the estate in this process until stopped (Ctrl+C or 'runtime stop'); refuses when a daemon already serves it.

Usage: `vericairn runtime serve [options]`

Options:
- `--no-loopback`: Disable the pinned loopback TLS endpoint. The local socket and any configured local-network listener remain available.
- `--detached`: Write the daemon's output to its log beside the estate's live store instead of the standard streams; 'runtime start' serves this way.

### `vericairn runtime start`

Start a daemon for the estate in the background and wait until it answers.

Usage: `vericairn runtime start [options]`

### `vericairn runtime stop`

Ask the daemon serving the estate to stop; closing a client never stops it.

Usage: `vericairn runtime stop [options]`

### `vericairn runtime status`

Whether a daemon serves the estate and where, or whether commands run the embedded runtime.

Usage: `vericairn runtime status [options]`

### `vericairn runtime install`

Install the daemon as a per-user service that starts at login (launchd agent, systemd user unit or a logon task).

Usage: `vericairn runtime install [options]`

Options:
- `--plan`: Show the unit and the commands without installing anything.

### `vericairn runtime uninstall`

Remove the per-user service installed by 'runtime install'.

Usage: `vericairn runtime uninstall [options]`

### `vericairn runtime configure`

Configure the runtime of this estate on this machine; without options, show the configuration. Nothing listens beyond the local socket and loopback unless an address is set.

Usage: `vericairn runtime configure [options]`

Options:
- `--local-network <local-network>`: The address and port the local-network profile listens on from the runtime's next start, an IP address of this machine such as 192.168.1.20:7443; 'off' turns it off. Off unless set.
- `--allow-public`: With --local-network, allow a wildcard address (every interface) or one other networks can reach; such an address is refused without it.

### `vericairn runtime rotate`

Replace the runtime certificate now (it is also replaced on a schedule before it expires). Paired devices keep working, since they pin the runtime identity, which signs the certificate in use; loopback clients read the new one from the endpoint file.

Usage: `vericairn runtime rotate [options]`

Options:
- `--compromised`: The certificate's key may be known to someone else: also close every open connection, so nothing continues under it.
- `--identity`: The runtime identity's key may be known to someone else: replace the identity too; every paired device then pairs again.
- `--reason <reason>`: Why, for the runtime's log.

## `vericairn docs`

Documentation: a release's set (its notes from the estate's records, and the check that a set holds every document its manifest lists; the references are generated by the product's own build tooling), and the living documents that stay true as the estate changes.

Usage: `vericairn docs [command] [options]`

Verbs: `notes`, `check`, `living`, `review`, `declare`, `regenerate`

### `vericairn docs notes`

Write release notes from the estate's records since the previous release's notes ended, and record their window in the set's manifest.

Usage: `vericairn docs notes [options]`

Options:
- `--from <from>`: The earlier published release's version; the notes begin where the notes of its documentation set, the directory it names beside --out, ended (at its publication when there is no such set). Required.
- `--to <to>`: The release's version; its publication ends the notes once it is recorded, the second before they are generated until then. Required.
- `--out <out>`: Directory of the documentation set the notes belong to. Required.
- `--since <since>`: The time the notes begin, for example 2026-10-15T12:06:00Z, instead of where the previous set's notes ended; needed when those record no window and state no end that can be read.

### `vericairn docs check`

Refuse a documentation set that lacks a document, or a heading for a command, an API operation or a record type its manifest lists; every gap is listed at once.

Usage: `vericairn docs check <directory> [options]`

Arguments:
- `<directory>`: The documentation set to check.

Options:
- `--documents <documents>`: The product's declaration of the documents every set holds (a JSON array of file names); the set's manifest is checked against it.

### `vericairn docs living`

List the declared living documents: each one current, due with every trigger newer than its latest clearance, or unavailable.

Usage: `vericairn docs living [options]`

### `vericairn docs review`

Record a review of a living document: the runtime reads its content, records the covered paths' identity and the triggers it answers, and runs its declared checks; a failed check refuses the clearance.

Usage: `vericairn docs review <path> [options]`

Arguments:
- `<path>`: The document's repository-relative path.

Options:
- `--by <by>`: The reviewing principal (ULID). Required.
- `--outcome <outcome>`: current (it holds), revised (it was changed for the trigger) or needs-change (it is stale and stays due). Required.
- `--summary <summary>`: What was checked. Required.
- `--finding <finding>`: A finding, severity:summary with severity error, warning or info; repeatable.
- `--commit <commit>`: For a document of another repository, the commit reviewed.
- `--independence <independence>`: For a document of another repository, whose author the estate's records do not show, the reviewer's independence of its content: self (the reviewer wrote or revised it), independent-agent or operator. Default: self for a principal that holds the builder role, else judged from the estate's records. An estate file's revisions decide its reviewer's independence, and a statement that differs is refused.

### `vericairn docs declare`

Record or revise the declaration of a living document: its triggers and levels, generated regions, checks and who may clear it.

Usage: `vericairn docs declare [options]`

Options:
- `--by <by>`: Authoring principal id (ULID). Required.
- `--body <body>`: Path to a JSON file holding the living-document declaration, or '-' for standard input. Required.
- `--supersedes <supersedes>`: The declaration this one revises.

### `vericairn docs regenerate`

Rewrite an estate document's generated regions, or a generated document, from their generators; nothing outside the markers changes.

Usage: `vericairn docs regenerate <path> [options]`

Arguments:
- `<path>`: The document's repository-relative path.
