# FIX-165: Windows batch programs start through the system's cmd.exe, and an absolute path without an extension takes .exe or .com

## docs/operator-guide.md

### In "7. Repositories and checks as evidence", after the paragraph beginning "From 0.9.4 (FIX-161), git, gitleaks and gh must be in an absolute directory"

> From 0.9.4 (FIX-165), on Windows a `check run` command, a launcher's `command` or a workspace setup command that is a batch
> program (`.cmd` or `.bat`, such as the shim npm installs for a harness) runs through `cmd.exe` in the system directory
> (`%SystemRoot%\System32`), never one that `ComSpec` or `PATH` names, inside the same job, and its exit code is the script's.
> Each argument reaches the script as data: one holding a space or any of `& | < > ^ ( ) ! = , ;` is quoted, and a double quote
> inside it is doubled. A program the script hands its arguments on to with `%*`, as npm's shims hand them to Node.js, reads each
> argument as given; the script's own `%~1` reads a double quote inside an argument as two. What `cmd.exe` cannot read as data is
> refused before anything starts, with the reason: a percent sign or a line break (or another control character) in an argument or
> the script's path, and a command longer than 8191 characters; `worker configure --setup-command` refuses such a setup command
> when you configure it. An absolute path without an extension, such as one ending in `\tools\harness`, starts that folder's
> `harness.exe`, else its `harness.com`, and nothing from another folder. The [software
> guide](software.md#coding-agents-the-worker-and-its-launchers) gives the exact command `cmd.exe` is given.

## docs/limitations-and-platforms.md

### In "Worker launchers, limits and custody", after the paragraph beginning "The custody guard refuses unattended launch"

> From 0.9.4 (FIX-165), on Windows a harness command, a workspace setup command or a `check run` command that is a batch program
> (`.cmd`, `.bat`) runs through the system directory's `cmd.exe`, which reads no percent sign and no line break or other control
> character as data: an argument or a script path holding one is refused before anything starts, and so is a command longer than
> the 8191 characters `cmd.exe` reads. The native launchers pass the goal condition as an argument, so a condition holding a
> percent sign or a line break refuses a run started through a `.cmd` shim npm installs for a harness; name the harness's own
> executable to start it without `cmd.exe`. A double quote inside an argument reaches a program the script hands its arguments on
> to (`%*`) as given only when that program reads its command line the C runtime's way, as Node.js does; the script's own `%~1`
> reads it doubled, since `cmd.exe` has no other way to write one. The launch binding hashes the script, not `cmd.exe`. An
> absolute path whose file name ends with a dot or a space, or that names a stream of a file, is refused.

## docs/api-compatibility-0.9.4.md

### After the section "Programs are started by their resolved absolute path (FIX-161)", before "Operations, the OpenAPI document, MCP and the record reader"

> ## Windows batch programs start through cmd.exe (FIX-165)
>
> No route, interface member, protocol type, record type or field changes, and no public member is added or changed.
> `BatchArgumentRefusedException`, a `Win32Exception` with native error 160, is a new internal type of `Vericairn.Records`
> (namespace `Vericairn.Records.Processes`), thrown before anything starts for a batch program whose path or arguments `cmd.exe`
> cannot read as data, so every caller that handles a start that fails handles it. On Windows a program whose extension is `.cmd`
> or `.bat` is no longer passed to `CreateProcessW` as the application name: the containment primitive and every other start pass
> `cmd.exe` from the system directory, with `/d /e:on /v:off /s /c` and the script's quoted path and arguments. An absolute
> Windows path without an extension resolves to the `.exe`, else the `.com`, of that name in its folder, where FIX-161 used it as
> given and the start failed; one whose file name ends with a dot or a space, or that names a stream of a file, is refused with
> `ProgramNotFoundException`. Behavior change of public members: on Windows `WorkerConfigurationStore.WriteSetup`
> (`Vericairn.Runtime`) refuses, with `ProviderRefusedException`, a batch setup command with an argument holding a percent sign or
> a control character other than a tab, and `ReadSetup` refuses, and `ListSetup` lists with its problem, a stored one. A launch
> binding's executable hash is of the script for a batch program, as before, and of the `.exe` or `.com` an absolute path without
> an extension resolves to. No record, record format or wire value changes.
