# FIX-175: Refuse a failed Secure Enclave helper and preserve the daemon identity

## docs/operator-guide.md

### In "3. Principals, devices and admission", after the paragraph beginning "**Custody.** A new device gets the strongest custody"

> From 0.9.5 (FIX-175), a present macOS helper must complete its availability check. A failure to start, an unexpected exit,
> a signal or a timeout makes `devices create` refuse before making a key. Exit 3 means no Secure Enclave is available to the
> process. A Mac with that result or with no helper uses file custody by default. `doctor` marks an unusable Secure Enclave
> default as unavailable. The daemon refuses to start if the helper fails while it reads its held Secure Enclave identity.
> It preserves the key and identity file, so paired devices keep their pin. Put the helper from this command line's release
> archive beside it and retry. The refusal omits the helper's path.
