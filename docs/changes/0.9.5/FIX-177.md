# FIX-177: Retain progress target comment attempts across follower restarts

## docs/limitations-and-platforms.md

### In "Progress target limits (0.9.4)", replace the bullet beginning "A comment that `gh` may have added" with

> - From 0.9.5 (FIX-177), a follower with its target's local state intact calls the adapter to send a comment at most once per recorded event or wait key. It saves the payload hash, form and destination before the call and keeps that original entry through changes to the text, form or destination. A comment with an uncertain or missing outcome appears in `vericairn progress target list` for a person to check. An adapter without comment receipt lookup, including GitHub Discussions, cannot prove that the request reached the service, that the comment was accepted or that readers were notified. A request interrupted before dispatch can therefore remain unsent. This protection starts with attempts recorded by this version and ends when the target or its state is removed. A refresh brings the report up to date on restart even when the journal can no longer replay missed events for comments. A wait's entry guards only while it waits: once it ends, a commented or refused entry is dropped, so the same ask, request or step waiting again is commented on again, and an uncertain one is kept for a person as `ended:<time>:<key>`. One follower follows a target on a machine at a time.
