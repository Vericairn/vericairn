# ID-17: A device's signatures and revocation reach

## docs/operator-guide.md

### In "3. Principals, devices and admission", after the paragraph beginning "`devices create` generates the key"

> From 0.9.5 (ID-17), run `vericairn devices reach <device> --since <time>` to see which available records a suspected device signed, including superseded records and signatures by its earlier keys. Where the local presence ledger has the evidence, the report includes the session's announced list. `devices revoke` reports the runtime that wrote the revocation and the server that handled the write, where applicable. `devices reach` shows revocation records in this copy and retained observations from this machine's daemon journal. Run it against other copies for evidence kept there. See [Devices reach](cli.md#vericairn-devices-reach-095) for the timestamp and JSON forms.

## docs/api-v1.md

### After the routes table entry for `POST /v1/devices/revoke`

> From 0.9.5 (ID-17), the revocation's write outcome may also carry `revocationReach`. Each entry gives the observer's `kind` (`runtime` or `server`), `identity`, time `at` and `evidence`. The writing runtime reports `written` and the server that handled the API write reports `write-served`. The evidence refers to the outcome's exact `written` record.
