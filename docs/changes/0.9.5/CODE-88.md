# CODE-88: Acquiring a repository runs nothing

## docs/operator-guide.md

### In "7. Repositories and checks as evidence", after the paragraph beginning "The overrides also apply"

> From 0.9.5 (CODE-88), source inspection, adoption, observation and clone registration use a temporary Git view that Vericairn owns. These commands report the SHA-256 of the exact configuration and the names of settings they ignored, with subsection names masked because they can contain credentials. They accept `--boundary <directory>` when Git metadata legitimately lives elsewhere under an operator-selected directory. Without that option the repository root is the boundary. A registered clone has to remain readable within its own root because later reads use that boundary. Source reads name and refuse an outside Git redirection, an unsafe index path or a working-tree entry they cannot copy as a bounded regular file.
>
> A worker acquires the named base commit into its own repository without submodules or repository-defined programs. If it finds any Git settings outside the allow-list, including an ordinary clone's upstream settings, a human operator must sign a passing `review` of the exact repository resource revision. Run `vericairn records new review --by <operator-id> --subject resource:<resource-id>:<resource-hash> --body <review.json>` with the operator's admitted device. Set `outcome` to `pass` and include `independence`, `summary` and `findings` as for other reviews. Set `repositoryConfiguration.config` to the reported SHA-256 and, when present, `repositoryConfiguration.worktreeConfig` to the reported worktree configuration hash. An edit to either configuration file requires review of the new bytes. Ignored settings stay ignored during acquisition.
>
> Before upgrading from an earlier release, retain any running worker's work through its existing runtime. A workspace with an alternate object store is refused for reuse or retention under 0.9.5 because the alternate can point outside the workspace. Preserve existing commits and files and prepare a new independent workspace for a later run.

## docs/limitations-and-platforms.md

### In "Reading repositories Vericairn did not create", after the section's description of isolated Git reads

> From 0.9.5 (CODE-88), source observations use private copies of Git metadata and regular working-tree files. Working-tree copies are limited to 64 MiB per file, 512 MiB total, 100,000 entries and 30 seconds. A tracked file that is a symbolic link, hard-linked or special, or would exceed a limit, refuses the observation as a whole and identifies the entry, as do a nested repository, an unreadable entry and the entry count or deadline. An untracked file's name is all Git's status reads of it: one that is a link, special, hard-linked or unreadable, or would exceed a byte limit, is never read and keeps only its name, so it is reported as untracked. Untracked content is copied within a 64 MiB budget of its own, so build outputs never use up the budget tracked files need; ignored and untracked files share that budget, so a large ignored tree can leave an untracked document withheld. One read sees the machine's own Git configuration, for line endings alone: the system and global `core.autocrlf` and `core.eol`, as Git for Windows sets them, are carried into the comparison when they are plain values, and the repository's own setting wins; no other system or global setting is read. Withheld content is never part of a policy read, a decision basis or any other recorded basis: a read that needs it is unavailable, and a name Git itself counts as tracked refuses the read. Gitlink directories are skipped. A local `git clone` from or into a repository shares its Git object files through hard links; remove the other clone, or replace the repository with an independent clone made with `git clone --no-hardlinks`. `sources inspect`, `sources adopt`, `sources clone` and workspace preparation name the hard link and this remedy; reads that only answer whether a commit or file exists (policy and document sources, coverage) report the repository as unreadable or the commit as missing instead, so inspect a repository that reads that way. Git metadata copies are limited to 4 GiB and 100,000 entries per copied store, with a 30-second acquisition deadline checked between file operations. Observed remote addresses are limited to HTTPS, SSH and local paths under the selected boundary. Retention uses the files reference format and does not create a reflog entry for its guarded local ref write. It adds to the registered clone only the objects the run's commits introduce beyond what the clone's own branches, remote branches and tags reach, packed in the workspace's runtime-owned view and checked object by object before it is published; a commit a reused workspace never retained travels with the rest. A workspace holding a shallow file, which Vericairn never writes, is refused by the scope audit and by retention. A pack already in the clone under the same name is left whole.
