# FIX-178: Preserve unreadable Secure Enclave runtime identities

## docs/operator-guide.md

### In "19. Pairing, local-network connections and revocation", after the paragraph beginning "Revocation is checked on the next request"

> From 0.9.5 (FIX-178), startup of the local-network profile preserves a saved Secure Enclave runtime identity
> when its key cannot be read, and refuses with a remedy for the failure: use the Mac that holds the key, restore its blob or
> record from a backup, or settle the helper. To keep serving here with a new identity, stop the runtime and run
> `vericairn runtime rotate --identity --replace-unreadable`, which also covers a machine with no usable Secure Enclave, where
> the new identity takes the custody the machine offers. It keeps the replaced record beside the new one and removes no key
> blob. Start the runtime again after rotation. Every paired device must pair again. See the CLI reference's "Recovering a
> runtime identity".
