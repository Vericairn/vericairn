# FIX-168: Release-basis evidence passes the checked push's scan

## docs/limitations-and-platforms.md

### In "Checked changes and operator actions", in the paragraph beginning "Checked pushes need an installed Gitleaks scanner": after the sentence ending "and there is still no per-estate allowance."

> From 0.9.5 (FIX-168), the scan also passes the git revisions a release basis records, which gitleaks' Sourcegraph rule reads
> as tokens wherever a basis names Sourcegraph, as one listing a file such as `DocumentSourceGraph.cs` does; 0.9.4's candidate
> records were refused for 33 such commit ids. The scanner reads each release basis the pushed commits add in the root's
> `objects/` folder, held as one object named by its hash or as a split object's parts and root, and allows, for that rule alone,
> exactly the commit ids the basis records for its submission, its repositories and their tree comparisons, in exactly the
> objects that hold its bytes. The allowance trusts the basis's form, not its signature: a value written in a revision's position
> passes, as a commit id does. Any other value, rule or path is scanned as before, so a secret beside the revisions is found, as
> is part of a split basis pushed without its root. When a split basis's part begins or ends inside one of the hashes the basis
> records and leaves exactly 40 of its digits alone at its edge, those digits are found, and such a push is made outside the
> checked flow.
