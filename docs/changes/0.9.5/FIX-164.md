# FIX-164: Remote pairs on Android without ending the app

## docs/limitations-and-platforms.md

### In "Pairing and the local-network profile", after the item beginning "The local-network transport uses mutual TLS 1.2"

> - From 0.9.5 (FIX-164), an Android phone offers no cipher-suite list. .NET 10's TLS on Android takes none, and when given one
>   it refuses it only after making its native TLS stream, whose release then ends the process: before 0.9.5, Remote closed when
>   Pair was tapped. The runtime chooses from its own list, which it applies on Linux and macOS (on Windows, the system's own
>   order puts the local network's suites first), and the phone refuses a handshake that ended on any other suite before it sends
>   anything. The SDK also refuses, before the handshake, any other option .NET's Android TLS would refuse at that point, and
>   reports a TLS setup failure as a refused connection. The fault itself lies in .NET's Android TLS, and a native failure while
>   that TLS makes its stream would still end the process.

## docs/api-v1.md

### In "A connection.", the paragraph beginning "**A connection.** The local network speaks TLS 1.2 only": replace "(on Windows, whose TLS takes no list from an application, the system's own order, which puts these first)" with

> (on Windows, whose TLS takes no list from an application, the system's own order, which puts these first; from 0.9.5, on
> Android, whose .NET TLS takes no list either, the runtime's own list, and the phone refuses a handshake that ended on any
> other suite before it sends anything)

### In the SDK paragraph, after the sentence ending "its `Protocols` (TLS 1.2) and `CipherSuites` are what both ends of the local network speak."

> From 0.9.5 (FIX-164) `CipherSuites` is null on Android as on Windows, and a TLS setup failure while pairing or connecting over
> the local network is the `AuthenticationException` of a refused handshake, which `RuntimePairing` and the local-network client
> report as they report a refused handshake, never another exception.

## docs/api-compatibility-0.9.5.md

### Under the 0.9.5 changes

> `TlsScreenStream.CipherSuites` is null on Android from 0.9.5 (FIX-164), as on Windows; no public signature changes. A TLS setup
> failure while pairing or connecting over the local network is an `AuthenticationException` where another exception, such as
> `NotSupportedException`, could reach the caller before.
