# FIX-180: The runtime service carries its Vericairn home

## docs/operator-guide.md

### In "11. The daemon", after the paragraph beginning "`runtime serve` runs the daemon in the foreground"

> From 0.9.5 (FIX-180), `runtime install` captures the effective Vericairn home in the service unit. Its label includes the estate and a hash of the home, so installations for different homes have distinct names. `runtime install --plan` shows the captured home.
>
> `runtime status` looks for the estate's endpoint in the selected Vericairn home. It shows the serving daemon's home as `home` in text or `vericairnHome` in JSON. When an older daemon omits its home, status reports the home that contains its endpoint file. If that endpoint answers and names another home, status exits with an error and names both homes. When no daemon answers, text status names the home it checked.
>
> A service installed before 0.9.5 continues to use the default home. To move it to an estate's own home, run `vericairn --estate <clone> runtime uninstall` with `VERICAIRN_HOME` unset. Then set `VERICAIRN_HOME` to the estate's home and run `vericairn --estate <clone> runtime install --plan` and `vericairn --estate <clone> runtime install` with the same setting. Use that home for subsequent status and uninstall commands for this service.

## docs/api-v1.md

### In "One owner", after the paragraph beginning "where `<key>` is `local`"

> From 0.9.5 (FIX-180), the endpoint file also carries `vericairnHome`, the absolute path of the home the daemon opened. Older daemons omit this field. For an answering endpoint without the field, `vericairn runtime status` reports the home that contains the endpoint file. If the endpoint names a different home, the command exits with an error that names both homes.
