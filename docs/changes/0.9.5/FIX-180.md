# FIX-180: The runtime service carries its Vericairn home

## docs/operator-guide.md

### In "11. The daemon", after the paragraph beginning "`runtime serve` runs the daemon in the foreground"

> From 0.9.5 (FIX-180), `runtime install` captures the effective Vericairn home in the service unit. Its label includes the estate and a hash of the home, so installations for different homes have distinct names. `runtime install --plan` shows the captured home. `runtime status` shows the home of a serving daemon as `home` in text or `vericairnHome` in JSON. It reports an error if the daemon's home differs from the home selected for the command. When an older daemon omits its home, the command uses the home where it found the endpoint file.
>
> A service installed before 0.9.5 continues to use the default home. To move it to an estate's own home, run `vericairn --estate <clone> runtime uninstall` with `VERICAIRN_HOME` unset. Then set `VERICAIRN_HOME` to the estate's home and run `vericairn --estate <clone> runtime install --plan` and `vericairn --estate <clone> runtime install` with the same setting. Use that home for subsequent status and uninstall commands for this service.
